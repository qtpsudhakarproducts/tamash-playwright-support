Self-healing for Playwright

Your tests keep running when the UI changes.

A button is renamed, a field moves, and a test breaks even though the app works. tamash-playwright finds the element again on the live page, retries, and records what it did, so the build stays green and you see exactly what changed.

What you get

◎

Heals at run time

When an action cannot find its element, the page is read again and the element is located. The original arguments are kept on the retry.

 ✓

Makes heals permanent

apply-heals turns run-time heals into source changes, re-runs the tests with healing off to prove them, and opens a pull request in CI.

 ⇄

Your choice of model

Ollama, OpenAI, Anthropic, Gemini, a Claude or Copilot subscription, or a rule-based matcher with no AI and no network calls.

 ◐

Vision fallback

When the page structure is not enough, a screenshot goes to a vision model, if your provider supports one.

 ▤

Reports and logs

Every attempt is logged, healed or not: the provider, the selector it suggested, the token cost and where the locator lives in your code.

 ✦

Works with your coding agent

One command installs a skill for Claude Code, Cursor, Copilot, Windsurf, Kiro or Zed that runs the whole heal-review-fix loop.

How it works

  1. A locator breaks

    Playwright cannot find the element. Without healing, the test fails here.

  2. The element is found again

    The healer reads the live page, asks the provider where the element went, and checks the answer against the page before using it.

  3. The test continues

    The action is retried and the heal is recorded. If it cannot be healed, the test fails as it would in stock Playwright.
